使用 GitHub Copilot 智能体模式时，Copilot 会自主探索代码库、提出更改、编辑文件并运行命令。由于这些操作实时发生在本地计算机上，VS Code 中的 Copilot Chat 会持续显示工具调用和文件编辑。你可以查看每项差异、接受或撤销单项更改，并通过后续提示词调整或扩展任务，无需离开编辑器。

在本练习中，你将：

- 实时监视无障碍智能体的工作。
- 审查并接受建议的文件编辑。
- 在同一会话中引导智能体添加浅色模式开关，与高对比度模式并存。

## 场景

[练习 4][previous-lesson]中的无障碍自定义智能体正在实现高对比度模式。工作进行期间，设计团队又提出了浅色模式开关的需求，以便不习惯默认深色主题的用户使用。无需从头开始新对话，可以引导当前会话扩展工作范围。

## 监视 Copilot 的进度

Copilot Chat 视图会显示智能体执行的每个步骤，包括探索的文件、运行的命令和建议的编辑。每项文件编辑都会以内联差异的形式显示，并提供 **Keep** 和 **Undo** 控件。

1. 返回练习 4 中使用的 Copilot Chat 视图。
2. 智能体工作期间，滚动聊天内容查看每次工具调用，包括文件读取、文件编辑和需要运行的终端命令。
3. 智能体建议编辑文件时，差异会以内联方式显示：
   - 选择 **Keep** 接受更改。
   - 选择 **Undo** 撤销更改，让智能体重新尝试。
4. 也可以打开聊天顶部的 **Files changed** 指示器，查看智能体在此会话中修改的所有文件。

> [!NOTE]
> 如果工具调用要求权限（例如运行终端命令），智能体会暂停并显示 **Allow** 提示。只批准你认可的命令。

5. 等待智能体完成高对比度模式。它会显示总结所做更改的最终消息。

## 引导智能体添加浅色模式

高对比度模式完成后，在同一对话中扩展工作，添加浅色模式开关。同一会话会保留先前的上下文，包括已修改的组件、样式方案和 local storage 模式。

1. 在 Copilot Chat 输入框中发送以下后续提示词：

   ```plaintext
   做得不错！现在再添加一个浅色模式开关，与高对比度开关并列。浅色模式应遵循相同模式：使用 local storage 保存设置，并在界面中的同一区域提供入口。用户应能独立启用高对比度和浅色模式。
   ```

2. 智能体会检查已有更改，并提出添加浅色模式的修改。
3. 与高对比度模式一样，逐项审查新更改的差异，并使用 **Keep** 或 **Undo**。
4. 如果智能体的实现方向不符合预期，例如试图以不希望的方式重构开关界面，可以选择聊天输入框旁的 **Stop** 按钮停止任务，再发送澄清提示词。

> [!TIP]
> 引导正在进行的会话比从头开始更快。可以用后续提示词调整方案（例如“简化 CSS，改用 CSS 变量，避免重复选择器”）、纠正方向（例如“不要添加第三个开关，将浅色模式集成到现有设置面板”），或扩展范围（例如“为两个开关添加键盘快捷键”）。

## 检查工作集

提交前快速审查智能体修改的所有内容。

1. 在 VS Code 中打开 **Source Control** 视图。
2. 检查所有已更改文件。你应会看到 Astro 组件、样式和相关测试的更新。
3. 打开部分已更改文件并查看差异。确认实现包含自定义智能体要求的无障碍模式，包括可访问富互联网应用程序（ARIA）属性、键盘导航、语义化 HTML 和 local storage 持久化。
4. 确认满意后，在 Source Control 面板中暂存并提交更改。下一课会发布这些更改。

## 总结与后续步骤

你使用 Copilot Chat 智能体模式监视并引导正在进行的会话：逐项审查文件编辑、接受或撤销更改，并在保留上下文的同时发送后续提示词扩展工作。

本课中你：

- 实时监视了智能体的工作。
- 接受或撤销了单项文件编辑。
- 使用后续提示词引导正在进行的会话。

接下来，在[迭代 Copilot 的工作][next-lesson]时，将无障碍功能发布为拉取请求，并审查本实验中本地自定义智能体创建的更改。
